The Foundations

Step 0: The Brute Force Web

The "Web of Death"

In a standard collision system, every object checks every other object. This is O(N²). With just 60 objects, the CPU is already choked by thousands of unnecessary checks.

Step 1: The Problem

The $O(N^2)$ Trap

If you check every bullet against every enemy, you are checking 1,000 against 1,000. That is 1,000,000 operations per frame. This is the bottleneck that kills most Unity games.

Brute Force: 150 vs 150 Checks: 22,500 Complexity: O(N²)

In this simple point cloud, a brute force search checks every single dot. It doesn't matter if the dot is across the screen; the CPU still does the math. We need to filter by proximity first.

Step 2: The Grid

Spatial Partitioning

By dividing the world into a grid (buckets), we only check objects in our immediate neighborhood. The mapping is a simple integer division.

Cell = floor(Position / CellSize)

AABBs: 150 Narrow-Phase Checks: 0 Savings: 0%

The grid allows us to skip 80-90% of all calculations. We only bother with objects in the active cells.

Step 3: Non-Allocating Memory

Zero Garbage Optimization

In Unity, new List<T>() in an Update loop triggers the Garbage Collector. We solve this by Bucket Pooling.

// Instead of discarding empty lists, we recycle them
private Stack<List<T>> _pool = new();

private List<T> GetNewList() {
    return _pool.Count > 0 ? _pool.Pop() : new List<T>();
}

private void RecycleList(List<T> list) {
    list.Clear();
    _pool.Push(list);
}

By using a Stack pool for internal lists and an "Out List" pattern for queries, we can achieve millions of proximity checks with zero heap allocations.

PART TWO

High-Performance Architecture

Moving beyond Dictionaries and Lists into the realm of cache-friendly memory layouts.

Step 4: The Pro Level

Flattened Arrays & Prefix Sums

For the ultimate performance (as seen in Matthias Müller's Ten Minute Physics), we ditch Dictionaries and Lists entirely. We use Flat Arrays.

1. Counting Sort

Instead of adding objects to lists, we just count how many objects are in each cell. This is a single pass over your data.

2. Prefix Sum (The Map)

By accumulating those counts, we create a cellStart array. This tells us exactly where each cell's data begins in a contiguous block of memory.

The Müller Pattern: Linear Memory

The secret is Spatial Sorting. By re-ordering your actual particles in memory so that particles in the same cell are adjacent, you achieve Cache Locality.

  • No Pointers: The CPU doesn't have to "jump" around memory to follow List references.
  • Prefetching: The CPU sees you reading particles in a straight line and pre-loads the next ones into the cache before you even ask for them.
  • Burst Friendly: This layout is 100% compatible with Unity's Burst compiler, turning C# into optimized machine code.

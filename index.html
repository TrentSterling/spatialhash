Spatial Hashing
Deep Dive.

The $O(N^2)$ killer for Unity and the secret to clean, non-allocating proximity queries.

By Trent Sterling • Feb 14, 2026 • Unity Performance

You’ve seen it before: you add a few hundred units or projectiles to your scene, and suddenly the frame-time spikes. You open the Profiler, and there it is—a massive block of Physics.OverlapSphere or nested foreach loops.

The culprit is $O(N^2)$ complexity. If every object checks every other object, your game will inevitably crawl to a halt.

"If you're checking 1,000 objects against 1,000 objects, you're doing 1,000,000 checks per frame. A Spatial Hash turns that into a few dozen."

1. The Logic: Mapping Space to Memory

The core idea is spatial partitioning. Instead of one giant list of objects, we divide the world into a grid. Each "cell" in the grid is a bucket that holds references to objects inside it.

Cell = floor(WorldPosition / CellSize)

We take those 3D coordinates (X, Y, Z) and combine them into a single Key. This lets us use a Dictionary<int, List<T>> for $O(1)$ lookups. 

private int GetKey(Vector3 pos) {
    int x = Mathf.FloorToInt(pos.x / _cellSize);
    int y = Mathf.FloorToInt(pos.y / _cellSize);
    int z = Mathf.FloorToInt(pos.z / _cellSize);
    
    // The "Hash" part: Combine coordinates into one integer
    unchecked {
        int hash = 17;
        hash = hash * 23 + x;
        hash = hash * 23 + y;
        hash = hash * 23 + z;
        return hash;
    }
}

2. Zero-Allocation (Avoiding GC)

The biggest mistake developers make is returning a new List<T> from their query function. In Unity, this creates managed heap allocations that trigger the Garbage Collector, causing those annoying micro-stutters.

The "Out List" Pattern

To keep it non-allocating, the function should never return a list. Instead, it should fill a list that the caller provides.

3. PurrNet & Network Interest

This isn't just for collisions. If you're using a transport like PurrNet, bandwidth is your most limited resource. You shouldn't sync a player’s rotation to someone who is 200 units away and behind a wall.

Interest Management (AOI)

By using a Spatial Hash, the server can efficiently determine which "Observers" are in range of a "Subject."

  • Subject: Updates the hash with its position.
  • Server: Queries the hash at the Subject's position.
  • Transport: Only sends packets to the specific IDs returned by the hash.

PurrNet Synergy

Plug the Spatial Hash into PurrNet's Observer system to handle massive player counts with minimal bandwidth.

O(N) Collision

Standard collision is O(N²). A hash makes it nearly O(N) by only checking local neighbors.

AI Perception

NPCs can "hear" or "see" objects in nearby cells without scanning every object in the scene.

World Chunking

Map your procedural chunks to the hash for instant loading/unloading based on player movement.

4. Implementation Tips

Choosing Cell Size

A common trap is choosing a cell size that is too small (too many empty buckets) or too large (too many objects per bucket). The Sweet Spot: Set cellSize to roughly 2x your average query radius.

Dynamic Updates

Don't re-hash every object every frame. Only call Update() if the object's transform.hasChanged or if it has moved a significant distance.
